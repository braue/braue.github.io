    SSH (Secure Shell)#

    Overview#

    SSH (Secure Shell) is a cryptographic network protocol used to securely access and manage remote systems over an unsecured network. It provides confidentiality, integrity, and authentication for command-line access, file transfer, and tunneling.

    SSH operates at the application layer (Layer 7) and has largely replaced insecure protocols such as Telnet, rlogin, and rsh. It is foundational in Linux/Unix administration, network device management, automation, and secure file transfer.

    Terminology#

    • Client — system initiating the SSH connection.
    • Server — system accepting SSH connections.
    • Session — encrypted communication channel between client and server.
    • Key Pair — public/private cryptographic keys used for authentication.
    • Host Key — server’s identity key used to prevent man-in-the-middle attacks.
    • Known Hosts — client-side database of trusted server keys.
    • Cipher — encryption algorithm used to protect traffic.
    • MAC (Message Authentication Code) — ensures data integrity.
    • Tunnel / Port Forwarding — encapsulating other traffic inside SSH.

    Practical Use-Cases#

    • Secure remote administration of servers and network devices.
    • Engineering access to relays, switches, and routers.
    • Automation and configuration management (Ansible, scripts).
    • Secure file transfers (SCP, SFTP).
    • Encrypted tunneling of legacy or insecure protocols.
    • Bastion/jump hosts for segmented networks.

    Protocol Characteristics#

    Key Parameters#

    • Port: TCP 22 (default)
    • Transport: TCP
    • Encryption: AES, ChaCha20 (modern)
    • Key Exchange: Diffie-Hellman, ECDH
    • Authentication:
      • Password (discouraged)
      • Public key (preferred)
      • Certificate-based (OpenSSH CA)
    • Integrity: HMAC-SHA2

    SSH Versions#

    Version Status
    SSH-1 Obsolete, insecure
    SSH-2 Current and secure

    Best Practices#

    • Disable password authentication where possible.
    • Use key-based or certificate-based authentication.
    • Restrict SSH access via firewall rules or ACLs.
    • Rotate keys periodically and remove unused accounts.
    • Use strong ciphers and disable legacy algorithms.
    • Log and monitor SSH access attempts.

    Common Pitfalls#

    • Exposing SSH directly to the internet without protection.
    • Weak passwords or shared keys.
    • Leaving default credentials enabled.
    • Accepting unknown host keys without verification.
    • Using outdated SSH versions or weak ciphers.
    • Excessive privileges for SSH users.

    SSH Capabilities#

    Core Functions#

    Feature Description
    Remote Shell Secure command-line access
    SCP Secure Copy (file transfer)
    SFTP Secure File Transfer Protocol
    Port Forwarding Tunnel TCP traffic through SSH
    X11 Forwarding Secure GUI forwarding (legacy use)
    Agent Forwarding Delegates authentication credentials

    Port Forwarding Types#

    • Local Forwarding — forward local port to remote service
    • Remote Forwarding — expose local service on remote system
    • Dynamic Forwarding — SOCKS proxy over SSH

    Troubleshooting & Failure Modes#

    Symptoms#

    • Connection refused or timed out.
    • Authentication failures.
    • Host key verification warnings.
    • Session disconnects or freezes.
    • Slow or unresponsive connections.

    Root Causes#

    • SSH service not running or blocked by firewall.
    • Incorrect credentials or missing keys.
    • Host key mismatch or server reinstallation.
    • Incompatible cipher or key exchange settings.
    • Network latency or packet loss.
    • User permissions misconfigured.

    Fixes / Workarounds#

    • Verify TCP port 22 (or custom port) is reachable.
    • Confirm correct user, key, and permissions.
    • Check and update known_hosts entries carefully.
    • Enable verbose logging (ssh -v).
    • Review server-side SSH logs.
    • Update SSH client/server to modern versions.

    Field Test Methods#

    • ssh -v user@host for verbose diagnostics.
    • sshd -T to validate server configuration.
    • Port scans to confirm SSH availability.
    • Log inspection (/var/log/auth.log, /var/log/secure).
    • Key validation using ssh-keygen.
