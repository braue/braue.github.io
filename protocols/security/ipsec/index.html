    IPSec (Internet Protocol Security)#

    Overview#

    IPSec (Internet Protocol Security) is a suite of protocols used to secure IP communications by authenticating, encrypting, and ensuring integrity of IP packets.

    IPSec operates at the network layer (Layer 3) and is commonly used to build VPNs (Virtual Private Networks), secure site-to-site links, and protect sensitive data traversing untrusted networks such as the internet.

    It is widely deployed in enterprise networking, industrial control systems, cloud connectivity, and remote access solutions.

    Terminology#

    • SA (Security Association) — a unidirectional logical connection defining how traffic is secured.
    • IKE (Internet Key Exchange) — protocol used to negotiate SAs and cryptographic parameters.
    • ESP (Encapsulating Security Payload) — provides encryption, integrity, and authentication.
    • AH (Authentication Header) — provides integrity and authentication only (rarely used).
    • Tunnel Mode — encrypts the entire IP packet (common for VPNs).
    • Transport Mode — encrypts only the payload of the IP packet.
    • SPD (Security Policy Database) — rules defining which traffic is protected.
    • SAD (Security Association Database) — active security associations.

    Practical Use-Cases#

    • Site-to-site VPNs between corporate networks.
    • Remote access VPNs for users and administrators.
    • Secure communication over untrusted or public networks.
    • Protecting SCADA and industrial traffic across WAN links.
    • Cloud-to-on-prem and cloud-to-cloud connectivity.
    • Compliance-driven encryption of IP traffic.

    Protocol Characteristics#

    Key Components#

    • IKEv1 / IKEv2 — key exchange and SA negotiation.
    • ESP (IP protocol 50) — primary data protection mechanism.
    • AH (IP protocol 51) — integrity/authentication only.
    • NAT Traversal (NAT-T) — encapsulates IPSec in UDP for NAT compatibility.

    Key Parameters#

    • Ports / Protocols:
      • UDP 500 — IKE
      • UDP 4500 — IPSec NAT-T
      • IP Protocol 50 — ESP
      • IP Protocol 51 — AH
    • Encryption Algorithms: AES, 3DES (legacy)
    • Integrity Algorithms: SHA-1 (legacy), SHA-2
    • Authentication: Pre-Shared Keys (PSK), Certificates (X.509)
    • Key Exchange: Diffie-Hellman groups

    Operating Modes#

    Mode Description
    Tunnel Mode Encrypts entire IP packet; most common for VPNs
    Transport Mode Encrypts payload only; used host-to-host

    Best Practices#

    • Prefer IKEv2 over IKEv1.
    • Use strong encryption (AES-GCM, SHA-256 or better).
    • Use certificate-based authentication where possible.
    • Enable Perfect Forward Secrecy (PFS).
    • Regularly rotate keys and certificates.
    • Limit IPSec policies to only required traffic.

    Common Pitfalls#

    • NAT issues without NAT-T enabled.
    • Mismatched encryption or authentication parameters.
    • Incorrect traffic selectors causing dropped packets.
    • Certificate expiration or trust chain failures.
    • Performance impact due to encryption overhead.
    • Difficulty troubleshooting encrypted traffic.

    IPSec Packet Flow Overview#

    Phase Description
    IKE Phase 1 Establishes secure control channel and authenticates peers
    IKE Phase 2 Negotiates IPSec SAs for data traffic
    Data Transfer Encrypted traffic exchanged using ESP
    Rekeying Periodic renegotiation of keys and SAs
    Teardown SAs expire or are explicitly deleted

    Troubleshooting & Failure Modes#

    Symptoms#

    • VPN tunnel fails to establish.
    • Tunnel is up but no traffic passes.
    • Intermittent connectivity drops.
    • Slow throughput or high latency.
    • Authentication or key negotiation errors.

    Root Causes#

    • Mismatched IKE/IPSec parameters.
    • Firewall blocking required ports or protocols.
    • NAT devices interfering with ESP traffic.
    • Incorrect routing or traffic selectors.
    • Expired or invalid certificates.
    • MTU or fragmentation issues.

    Fixes / Workarounds#

    • Verify encryption, hashing, and DH group settings on both peers.
    • Ensure UDP 500 and 4500 are allowed through firewalls.
    • Enable NAT-T when NAT is present.
    • Check routing and protected subnets.
    • Adjust MTU or enable fragmentation handling.
    • Review logs for IKE negotiation failures.

    Field Test Methods#

    • Device logs (ike, ipsec, or VPN debug logs).
    • Packet capture (verify IKE/ESP negotiation).
    • Test connectivity before and after tunnel establishment.
    • Validate routing tables and traffic selectors.
    • Use diagnostic commands (show vpn, show ipsec sa).

    • RFC 7296 — IKEv2
    • RFC 3947 / 3948 — NAT Traversal
    • NIST SP 800-77 — Guide to IPSec VPNs
    • Vendor Documentation — platform-specific IPSec implementations
