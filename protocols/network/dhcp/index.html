    DHCP (Dynamic Host Configuration Protocol)#

    Overview#

    DHCP (Dynamic Host Configuration Protocol) is a network protocol that automatically assigns IP addresses and other network configuration parameters to devices on a network.

    DHCP simplifies IP address management, ensures proper subnet configuration, and supports centralized management of network parameters such as default gateway, DNS servers, and lease times. It is widely used in enterprise networks, industrial LANs, and service provider networks.

    Terminology#

    • DHCP Client — device requesting IP configuration (e.g., PC, IoT device, relay).
    • DHCP Server — authoritative device providing IP addresses and configuration.
    • IP Lease — temporary allocation of an IP address to a client.
    • DHCP Scope / Pool — defined range of IP addresses available for assignment.
    • DHCP Discover / Offer / Request / Ack — primary message types in the DHCP handshake.
    • DHCP NACK — message indicating a requested IP cannot be assigned.
    • DHCP Relay / Agent — intermediary forwarding DHCP messages between clients and servers across subnets.
    • Option / Parameter — additional network settings delivered by DHCP (e.g., DNS, gateway, domain name).

    Practical Use-Cases#

    • Automatic IP assignment for client devices in enterprise networks.
    • Configuration of SCADA, PLCs, and industrial devices without manual IP setup.
    • Simplified network management in large campus networks.
    • Temporary or dynamic IP allocation in service provider or cloud networks.
    • Support for mobile devices and wireless networks.

    Protocol Characteristics#

    Key Parameters#

    • Ports: UDP 67 (server), UDP 68 (client)
    • Transport: UDP (connectionless, requires broadcast for initial discovery)
    • Message Types: Discover, Offer, Request, Ack, NACK, Release, Inform
    • Lease Duration: Configurable per scope; determines how long a client may use an IP.
    • Options: Network configuration parameters including gateway, DNS, subnet mask, domain name, TFTP server, etc.

    Best Practices#

    • Segment DHCP scopes per subnet or VLAN to avoid IP conflicts.
    • Use DHCP reservations for critical devices (relays, servers, routers).
    • Configure redundant DHCP servers for high availability.
    • Monitor lease usage and enforce appropriate lease times.
    • Secure DHCP with trusted relay agents and optional authentication in sensitive environments.

    Common Pitfalls#

    • IP exhaustion due to undersized scope or rogue clients.
    • Duplicate IP addresses from misconfigured static assignments.
    • Misconfigured DHCP relay or firewall blocking DHCP traffic.
    • DHCP server misconfiguration causing clients to fail obtaining IP addresses.
    • Broadcast domain issues preventing DHCP discover messages from reaching the server.

    DHCP Message Flow Overview#

    Message Type Description
    DHCP Discover Client broadcasts to locate available DHCP servers.
    DHCP Offer Server responds with an available IP address and network parameters.
    DHCP Request Client requests the offered IP address from a specific server.
    DHCP Ack Server confirms assignment and provides full configuration.
    DHCP NACK Server denies the requested IP assignment.
    DHCP Release Client releases the IP address back to the pool.
    DHCP Inform Client requests additional configuration parameters without changing IP.

    Troubleshooting & Failure Modes#

    Symptoms#

    • Clients cannot obtain IP addresses.
    • IP conflicts or duplicate addresses on the network.
    • Incorrect gateway, DNS, or subnet mask configuration.
    • Intermittent connectivity due to lease expiration or renewal issues.
    • DHCP offers not reaching clients across subnets.

    Root Causes#

    • DHCP server down or unreachable.
    • Broadcast traffic blocked by firewalls or VLAN segmentation.
    • Exhausted DHCP scope or pool.
    • Misconfigured relay agents or IP helper addresses.
    • Incorrect DHCP options (gateway, DNS) configured on server.

    Fixes / Workarounds#

    • Verify DHCP server is running and accessible.
    • Ensure UDP ports 67/68 are open and allowed across the network.
    • Expand DHCP scope or reclaim unused leases.
    • Configure relay agents correctly for multi-subnet networks.
    • Validate DHCP options for proper network configuration.

    Field Test Methods#

    • ipconfig /renew (Windows) or dhclient (Linux) to test client lease assignment.
    • Capture DHCP packets with Wireshark or tcpdump to inspect Discover/Offer/Request/Ack flow.
    • Monitor DHCP server logs for errors or lease utilization.
    • Test relay agent functionality in multi-subnet environments.
    • Check IP conflicts and lease expiration behavior.

    Standards & References#

    • RFC 2131 — DHCP Protocol Specification.
    • RFC 2132 — DHCP Options and Parameters.
    • RFC 1542 — BootP Relay and related considerations.
    • IETF DHCP Working Group — updates, best practices, and extensions.
