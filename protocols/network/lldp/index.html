    LLDP (Link Layer Discovery Protocol)#

    Overview#

    LLDP (Link Layer Discovery Protocol) is a vendor-neutral, Layer 2 discovery protocol used by network devices to advertise and discover information about directly connected neighbors.

    LLDP allows switches, routers, firewalls, servers, and industrial devices to exchange identity, capability, and configuration information. It is widely used for topology discovery, network documentation, troubleshooting, and automation.

    Terminology#

    • TLV (Type-Length-Value) — the encoding format used for LLDP information elements.
    • Chassis ID — uniquely identifies the sending device.
    • Port ID — identifies the sending interface.
    • TTL (Time To Live) — how long received LLDP information remains valid.
    • LLDPDU — LLDP Data Unit; the packet exchanged between neighbors.
    • Neighbor Table — locally stored information learned via LLDP.
    • Optional TLVs — additional advertised data such as system name, VLAN, or power info.

    Practical Use-Cases#

    • Automatic discovery of network topology.
    • Identifying which device and port is connected where.
    • Validating cabling and patching during commissioning.
    • Supporting VoIP phone and access point deployment.
    • Network inventory, documentation, and automation.
    • Troubleshooting miswired or unexpected connections.

    Protocol Characteristics#

    Key Parameters#

    • OSI Layer: Layer 2 (Data Link)
    • Transport: Ethernet (no IP required)
    • Multicast Address: 01:80:C2:00:00:0E
    • EtherType: 0x88CC
    • Direction: Bidirectional neighbor advertisements
    • Default Interval: Typically 30 seconds (vendor configurable)
    • TTL: Usually 120 seconds (4× advertisement interval)

    Mandatory TLVs#

    LLDP frames must include:

    • Chassis ID TLV
    • Port ID TLV
    • Time To Live (TTL) TLV

    Common Optional TLVs#

    • System Name
    • System Description
    • System Capabilities
    • Management Address
    • Port Description
    • VLAN / QoS information
    • Power via MDI (PoE) details

    Best Practices#

    • Enable LLDP on access and aggregation switches.
    • Use LLDP for documentation and topology mapping.
    • Disable LLDP on untrusted or external-facing interfaces if needed.
    • Standardize LLDP intervals across the network.
    • Monitor LLDP neighbor tables for unexpected devices.

    Common Pitfalls#

    • LLDP disabled by default on some devices.
    • Confusion between LLDP and vendor-specific discovery protocols.
    • Stale neighbor entries due to TTL mismatch.
    • Security concerns when advertising too much device information.
    • Assuming LLDP works across routed boundaries (it does not).

    LLDP Frame Structure#

    Field Description
    Chassis ID TLV Identifies the sending device
    Port ID TLV Identifies the sending interface
    TTL TLV Validity timer for the advertisement
    Optional TLVs Additional system and port information
    End of LLDPDU TLV Marks end of the LLDP frame

    Troubleshooting & Failure Modes#

    Symptoms#

    • No LLDP neighbors displayed.
    • Incorrect or missing device information.
    • Topology maps incomplete or inaccurate.
    • VoIP phones or APs not auto-configuring.
    • Unexpected devices appearing on ports.

    Root Causes#

    • LLDP disabled on one or both sides of the link.
    • LLDP filtered by switch configuration or security policies.
    • Incompatible LLDP versions or TLVs.
    • Incorrect interface mode (access vs trunk).
    • Neighbor TTL expiration due to packet loss.

    Fixes / Workarounds#

    • Enable LLDP transmit and receive on interfaces.
    • Verify LLDP is not filtered or rate-limited.
    • Adjust advertisement interval and TTL if needed.
    • Use packet capture to verify LLDP frames on the wire.
    • Compare LLDP output on both ends of the link.

    Field Test Methods#

    • show lldp neighbors / lldpctl
    • Interface-specific LLDP neighbor commands
    • Packet capture with Wireshark (filter: eth.type == 0x88cc)
    • Verify MAC multicast reachability
    • Cross-check physical cabling and port labeling

    Standards & References#

    • IEEE 802.1AB — LLDP standard
    • RFC 4957 — LLDP Management Information Base
    • IEEE 802.3af / 802.3at / 802.3bt — PoE TLVs
    • Vendor Documentation — extended TLVs and configuration guidance
