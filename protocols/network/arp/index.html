    ARP (Address Resolution Protocol)#

    Overview#

    ARP (Address Resolution Protocol) is a network protocol used to map layer 3 IP addresses to layer 2 MAC addresses on a local area network (LAN).

    ARP operates within a broadcast domain to allow devices to determine the hardware address of a host given its IP address. It is fundamental to Ethernet communication and is used extensively in IP-based networks to enable packet delivery on local subnets.

    Terminology#

    • IP Address — logical network-layer address assigned to a host.
    • MAC Address — hardware address assigned to a network interface card (NIC).
    • ARP Request — broadcast message asking “Who has IP X.X.X.X?”
    • ARP Reply — unicast response providing the MAC address for the requested IP.
    • ARP Table / Cache — mapping of IP addresses to MAC addresses stored on a host or switch.
    • Gratuitous ARP — ARP broadcast sent by a host to announce or update its IP-to-MAC mapping.

    Practical Use-Cases#

    • Resolving MAC addresses to deliver Ethernet frames in LANs.
    • Network troubleshooting, such as detecting IP conflicts or ARP poisoning.
    • Switch MAC table population via ARP traffic.
    • Network monitoring and mapping tools (e.g., identifying hosts on a subnet).
    • Supporting VLANs and subnet communications in enterprise and industrial networks.

    Protocol Characteristics#

    Key Parameters#

    • Transport / Layer: Operates at Layer 2 (Data Link) and assists Layer 3 (IP).
    • Frame Type: Ethernet frame containing ARP opcode, sender/target IP/MAC addresses.
    • Message Types: Request, Reply, Gratuitous.
    • Cache Timeout: ARP table entries expire after a configurable period (commonly 60–120 seconds).
    • Broadcast Domain: ARP requests are broadcast to all devices on the same subnet.

    Best Practices#

    • Minimize unnecessary ARP broadcasts in large networks using static ARP entries or ARP caching.
    • Monitor ARP traffic for anomalies or potential attacks.
    • Use VLAN segmentation to limit ARP broadcast domains.
    • Combine with security features like Dynamic ARP Inspection (on managed switches) to prevent spoofing.
    • Clear stale ARP cache entries on network devices as needed.

    Common Pitfalls#

    • ARP cache poisoning / spoofing causing network attacks or misrouting.
    • Excessive ARP traffic in large broadcast domains leading to congestion.
    • Stale ARP entries preventing communication after device replacement or MAC change.
    • Misconfigured subnet masks causing ARP requests to fail.
    • Gratuitous ARP flooding in misconfigured networks.

    ARP Message Flow Overview#

    Message Type Description
    ARP Request Broadcast sent to ask “Who has IP X.X.X.X?”
    ARP Reply Unicast response with the MAC address corresponding to the requested IP.
    Gratuitous ARP Broadcast to announce a host’s IP/MAC mapping, typically used at startup or after IP changes.

    Troubleshooting & Failure Modes#

    Symptoms#

    • Hosts cannot reach other hosts on the same subnet.
    • Duplicate IP address warnings.
    • Intermittent connectivity within LAN.
    • Unexpected traffic rerouting or interception (potential ARP spoofing).
    • ARP table inconsistencies or missing entries.

    Root Causes#

    • Incorrect IP or subnet configuration.
    • MAC address changes not reflected in ARP cache.
    • Malicious ARP spoofing or poisoning.
    • Network loops or broadcast storms.
    • Device misconfiguration or failed interface.

    Fixes / Workarounds#

    • Clear or refresh ARP cache (arp -d or OS-specific commands).
    • Verify IP addressing and subnet mask configurations.
    • Use static ARP entries for critical devices if necessary.
    • Deploy security features like Dynamic ARP Inspection (DAI).
    • Monitor ARP traffic for anomalies using network analysis tools.

    Field Test Methods#

    • arp -a to view ARP cache on hosts.
    • Ping and trace to test MAC resolution and reachability.
    • Packet capture with Wireshark or tcpdump to inspect ARP requests and replies.
    • Network mapping tools to identify IP/MAC pairings.
    • Test duplicate IP detection and conflict resolution.

    Standards & References#

    • RFC 826 — ARP protocol specification.
    • IEEE 802.3 — Ethernet framing and addressing standards.
    • RFC 5227 — IPv4 Address Conflict Detection.
    • Cisco / vendor documentation — ARP security and monitoring practices.
