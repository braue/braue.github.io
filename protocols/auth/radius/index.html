    RADIUS (Remote Authentication Dial-In User Service)#

    Overview#

    RADIUS (Remote Authentication Dial-In User Service) is a network protocol used for centralized authentication, authorization, and accounting (AAA) of users and devices.

    RADIUS allows network devices (e.g., switches, VPN servers, Wi-Fi access points) to delegate authentication and policy enforcement to a centralized server, simplifying user management and enhancing security.

    RADIUS is widely used in enterprise networks, wireless LANs, VPNs, and network access control systems. It typically operates over UDP and supports integration with directory services like LDAP or Active Directory.

    Terminology#

    • AAA — Authentication, Authorization, Accounting; the core functions of RADIUS.
    • NAS (Network Access Server) — device that requests AAA services from a RADIUS server.
    • Client / Server — RADIUS client is typically a network device; the server processes requests.
    • Access-Request / Access-Accept / Access-Reject — primary authentication message types.
    • Access-Challenge — optional message prompting additional credentials or actions.
    • Accounting-Request / Accounting-Response — messages used for usage tracking.
    • Shared Secret — pre-shared key used to secure communication between client and server.
    • Attributes (AVPs) — Name-Value pairs that carry user and session information.

    Practical Use-Cases#

    • User authentication for wired or wireless network access.
    • VPN and remote access authentication.
    • Centralized network policy enforcement (e.g., VLAN assignment, ACLs).
    • Usage accounting and logging for billing or auditing.
    • Integration with LDAP/Active Directory for user credentials.

    Protocol Characteristics#

    Key Parameters#

    • Ports: 1812 (authentication), 1813 (accounting) — older implementations may use 1645/1646.
    • Transport: UDP (primary)
    • Security: Shared secret for message integrity; passwords encrypted (not end-to-end).
    • Authentication Methods: PAP, CHAP, MS-CHAPv1/v2, EAP variants.
    • Message Types: Access-Request, Access-Accept, Access-Reject, Access-Challenge, Accounting-Request, Accounting-Response.

    Best Practices#

    • Use RADIUS over secure networks or VPNs to prevent interception.
    • Use strong shared secrets and rotate them periodically.
    • Integrate with directory services (LDAP/Active Directory) for centralized credentials.
    • Enable logging and monitoring of authentication events.
    • Deploy redundant RADIUS servers for high availability.

    Common Pitfalls#

    • Weak or shared secrets leading to security vulnerabilities.
    • Mismatched authentication methods between client and server.
    • Firewall or NAT blocking UDP ports 1812/1813.
    • Incorrect attribute mapping causing failed VLAN assignments or access denial.
    • Lack of accounting configuration causing incomplete session logging.

    RADIUS Message Flow Overview#

    Message Type Description
    Access-Request Sent by client to request authentication.
    Access-Accept Server approves the request; user gains access.
    Access-Reject Server denies access based on credentials or policy.
    Access-Challenge Server requests additional information (e.g., OTP).
    Accounting-Request Client reports session start, stop, or interim updates.
    Accounting-Response Server acknowledges receipt of accounting information.

    Troubleshooting & Failure Modes#

    Symptoms#

    • Users unable to log in to network devices.
    • Authentication failures with correct credentials.
    • Access granted but incorrect VLAN or policy assignment.
    • Missing or incomplete accounting records.
    • Intermittent session drops or connection resets.

    Root Causes#

    • Incorrect shared secret between NAS and RADIUS server.
    • Misconfigured authentication method (PAP/CHAP/EAP).
    • Network firewall or port blocking UDP 1812/1813.
    • Attribute mismatch causing policy errors.
    • Server overload or downtime.

    Fixes / Workarounds#

    • Verify and synchronize shared secrets.
    • Confirm authentication method compatibility between NAS and server.
    • Ensure UDP ports 1812/1813 are open and properly routed.
    • Check attribute mappings for VLAN, ACLs, or other policies.
    • Test with known-good RADIUS client or tool (e.g., NTRadPing, radtest).
    • Deploy redundant RADIUS servers for high availability.

    Field Test Methods#

    • Test authentication using RADIUS client tools (e.g., radtest, NTRadPing).
    • Capture packets with Wireshark to validate message flow and attribute values.
    • Check logs on both RADIUS client and server.
    • Validate accounting entries for session start/stop and interim updates.
    • Simulate different authentication methods to ensure compatibility.

    Standards & References#

    • RFC 2865 — RADIUS Authentication Protocol.
    • RFC 2866 — RADIUS Accounting Protocol.
    • RFC 3579 — RADIUS Extensible Authentication Protocol (EAP) Support.
    • RFC 6613 — RADIUS Server Failover and Redundancy.
    • IETF RADIUS Working Group — ongoing updates and extensions.
