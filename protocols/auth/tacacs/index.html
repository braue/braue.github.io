    TACACS+ (Terminal Access Controller Access-Control System Plus)#

    Overview#

    TACACS+ is a network protocol used for centralized authentication, authorization, and accounting (AAA) of users and devices, primarily in network equipment environments.

    TACACS+ separates authentication, authorization, and accounting functions, offering greater flexibility and granular control than RADIUS. It is commonly deployed on routers, switches, firewalls, and other network devices to enforce administrative access policies.

    TACACS+ operates over TCP and encrypts the entire payload, providing strong security for administrative sessions.

    Terminology#

    • AAA — Authentication, Authorization, Accounting; the core functions of TACACS+.
    • NAS / Network Device — the client device requesting AAA services from the TACACS+ server.
    • Client / Server — TACACS+ client is typically a network device; server handles AAA requests.
    • Authentication — verifies user identity before access is granted.
    • Authorization — determines permitted commands or access levels after authentication.
    • Accounting — logs administrative actions or session information.
    • Shared Secret — pre-shared key used for encryption between client and server.
    • Command Authorization — TACACS+ allows per-command access control for granular security.

    Practical Use-Cases#

    • Centralized authentication for network administrators and engineers.
    • Fine-grained authorization of administrative commands on routers, switches, and firewalls.
    • Logging and auditing of device configuration changes for compliance.
    • VPN and remote access administrative control.
    • Integration with directory services (LDAP/Active Directory) for user credentials.

    Protocol Characteristics#

    Key Parameters#

    • Port: 49 (TCP)
    • Transport: TCP (reliable, connection-oriented)
    • Security: Entire payload encrypted; shared secret required.
    • Authentication Methods: PAP, CHAP, or ASCII-based authentication.
    • Separation of Functions: Authentication, Authorization, Accounting handled independently.

    Best Practices#

    • Use strong shared secrets and rotate them periodically.
    • Encrypt management traffic and avoid using TACACS+ over insecure networks.
    • Centralize device AAA to simplify administration and auditing.
    • Configure command authorization to limit administrative privileges.
    • Monitor logs for unusual or unauthorized activity.

    Common Pitfalls#

    • Misconfigured AAA separation causing failed authentication or missing authorization.
    • Weak or shared secrets allowing unauthorized access.
    • Network firewalls or ACLs blocking TCP port 49.
    • Insufficient logging or monitoring of accounting data.
    • Compatibility issues between network devices and TACACS+ server implementations.

    TACACS+ Message Flow Overview#

    Function Description
    Authentication Verify user identity before granting access.
    Authorization Determine which commands or resources the user can access.
    Accounting Record session details and commands executed.
    Start / Stop / Interim Session lifecycle messages for accounting and auditing.

    Troubleshooting & Failure Modes#

    Symptoms#

    • Users cannot log in to network devices.
    • Commands fail despite successful login.
    • Session logging incomplete or missing.
    • Unauthorized commands executed due to improper authorization.
    • Intermittent authentication failures.

    Root Causes#

    • Shared secret mismatch between client and server.
    • Misconfigured separation of AAA functions.
    • TCP port 49 blocked or filtered.
    • Outdated or incompatible TACACS+ server or client software.
    • Missing or incomplete accounting configuration.

    Fixes / Workarounds#

    • Verify and synchronize shared secrets.
    • Confirm AAA separation is correctly configured.
    • Ensure TCP port 49 is open and routed correctly.
    • Update TACACS+ server and client software.
    • Enable and review logging for both authentication and command execution.

    Field Test Methods#

    • Test authentication using TACACS+ client tools (e.g., Cisco test commands, tac_test).
    • Capture traffic using packet analyzers to confirm encrypted AAA message exchange.
    • Validate command authorization on a test device.
    • Check accounting logs for completeness and accuracy.
    • Simulate different user roles to verify authorization rules.

    Standards & References#

    • RFC 1492 — Original TACACS specification.
    • Cisco TACACS+ Implementation Documentation — Widely referenced implementation.
    • RFC 8907 — Best current practice for TACACS+ in modern networks.
    • IETF AAA Working Group — ongoing updates to authentication and authorization protocols.
